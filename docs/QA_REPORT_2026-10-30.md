## A. Test fix — `test/worker_home_v2_test.dart`

"zero-credit worker is ready and sees the free-jobs card" failed with
`Bad state: No element` at the second `scrollUntilVisible`.

Root cause: `scrollUntilVisible` finishes with `Scrollable.ensureVisible`,
which jumps the list **without pumping a frame**. The next
`scrollUntilVisible` judged visibility from the stale layout, and its 300 px
drags carried the list past the free-jobs card to the end of the list.
Fix: one `await tester.pumpAndSettle();` between the two scrolls (with a
comment). Same scrollable, same assertions, no delays, no production change.
Result: file passes 9/9.

## E. Functional testing (emulator, end to end)

Customer: signup → role via `initializeAccount` + claims → email verification
→ phone OTP → profile setup → home → explore → worker profile → post request
(photo, urgency, budget) → booking tracking → live tracking with a moving
worker (distance + "last updated" refresh in real time) → completion → 4★
review (stored; worker aggregate updated to 4.0 / 1 review / 1 job) → chat →
notifications → profile, settings, dark mode, help, support message.

Worker: signup → profile + photo upload → CNIC + selfie → submit verification
→ admin approval → lead appears → accept (contact shared server-side,
`live_tracking` activated) → On my way (location published) → Start → Complete
→ notifications → chat reply (read receipts) → SOS.

Admin: approve verification (audit entry, sanitized `public_profiles`), view
users/workers/jobs/reviews, investigate + resolve SOS, resolve support
request, audit log.

### Bugs found and fixed during the run

1. **Worker location sharing never worked on web** — `getLastKnownPosition`
   throws on web; the error was swallowed into "Location could not be
   updated". The cached fix is now optional. (`worker_jobs_repository.dart`)
2. **Chat could not be opened from a booking or job (both sides), or from a
   worker profile.** Rules only let participants read a chat, so (a) the
   `requestId`-only query was denied — now also filters by the caller's
   participant field; (b) reading a not-yet-created chat inside a transaction
   was denied — the chat is now read outside the transaction and "not visible"
   is treated as "create it", which the rules accept only for a new chat with
   the caller as participant. Rules unchanged. (`customer_chat_service.dart`,
   `worker_jobs_repository.dart`)
3. **Worker CNIC upload denied** by `verification_requests` rules — rewritten
   so a worker can save a draft/pending request but never touch review
   fields or self-approve; 4 new rules tests.
4. **Polyline decoding wrong on web** (`~` on JS ints) — fixed in
   `tracking_math.dart`.
5. **Editing the customer profile erased saved coordinates** (wrote
   `lat/lng: null` when no new GPS fix was taken). Fixed.
6. **Admin verification images spun forever** — admin app was not connected
   to the Storage emulator. Fixed (emulator mode only).
7. **Admin SOS actions were not in the audit log** — investigate/resolve/false
   alarm now write `admin_audit_logs` in the same batch.

## F. UI/UX review — fixed

- Dark mode: booking status chip and progress bar used light-mode green on a
  dark card (low contrast). Status colours are lifted for dark surfaces.
- Admin sidebar: selected item and divider still used the old navy
  `#1D2939`; now brand dark green.
- Admin Emergency alerts at 390 px: hero title broke mid-word
  ("Emergenc / y"). Hero now stacks on narrow widths.
- Map fallback card overflowed by 30 px in small map slots; it now drops the
  icon/button when there is no room.
- Admin dashboard showed "Customers" twice; second card is now
  "Support requests".
- Notification screen-reader labels doubled full stops ("request.. 10 min").
- Fonts bundled as assets (Inter, Poppins, OFL licences) so text renders
  without fetching from Google at runtime.

## F2. UI/UX observations — not changed (no redesign)

- Customer profile city defaults to Peshawar; a user who only types an area
  ("F-7 Markaz") gets "F-7 Markaz, Peshawar". Suggest no default / detect city.
- Worker job detail "0.0 km straight-line distance" is measured from the
  worker's saved area, not live GPS; label could say so.
- Messaging is hidden after a job is completed (by design?) — customers may
  want to message about follow-ups.
- Admin Emergency hero counts only `active`, while an `investigating` alert
  still needs attention ("No active SOS alert right now" while 1 is being
  investigated).
- Admin Jobs table truncates titles at 768–1024 px and needs horizontal
  scroll; Support requests page lacks the page title/intro other sections have.
- Admin stat cards stack one per row on phones (long scroll).
- Request image thumbnail of the tiny QA test image rendered as a grey box
  with a sliver — re-check with a real photo on device.
